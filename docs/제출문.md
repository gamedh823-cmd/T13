## 앱 한 문장

ChatGPT·Gemini·Claude에 질문을 쓰는 사람이 프롬프트를 붙여 넣으면, 이 앱이 그 안의 토론 지시·전문가 역할·다수 의견·구체적 설명 신호를 찾아 논문(T10)의 실험 수치로 정답률과 답 길이가 어떻게 달라지는지 알려 준다.

사용하는 논문 결과: H4 토론은 정답률을 바꾸지 못하고 답을 3~5배 길게 함(표 14·18), H3 전문가 역할은 일관된 효과 없음, H2 다수 의견은 AI마다 달랐음(표 12), H1 구체적 설명은 색 다양성을 낮춤(표 9).

## 짧은 확인 방법

1. **어디에 무엇이 있나**: URL을 열면 맨 위에 논문 제목과 앱 한 문장이 있고, 그 아래 1번 입력칸, 점검 결과, 2번 AI 선택, 3번 개선 제안이 순서대로 나온다. ZIP이면 압축을 풀고 `index.html`을 연다.
2. **사용자가 할 일 세 가지**
   - ① "예시로 해 보기"의 `토론 지시` 버튼을 누른다. 또는 프롬프트를 직접 붙여 넣고 `점검하기`를 누른다.
   - ② 2번 "논문에서는 답이 얼마나 달라졌나"에서 세 AI의 관찰된 길이 배율(ChatGPT 3.39배, Gemini 4.31배, Claude 5.42배)을 본다.
   - ③ 3번의 규칙 제안을 읽는다. (선택) `AI에게 고친 프롬프트 받기`를 누른다.
3. **통과 기준**
   - ① 결과에 "토론 지시" 카드가 나오고 "정답률은 안 바뀌고, 답만 3~5배 길어졌어요"와 ChatGPT 3.4배·Gemini 4.3배·Claude 5.4배가 보인다.
   - ② 세 AI의 배율 막대와 "평균 211자 → 714자, 정답 9/10 → 9/10" 같은 관찰값이 보인다. 토론·역할 신호가 없는 프롬프트에서는 이 카드가 나오지 않는다(예측하지 않음).
   - ③ 규칙 제안이 보인다. 버튼은 서버 응답이 오면 제안을, 실패하면 안내 문장을 보여 준다.
   - 잘못된 입력: 빈 칸에서 `점검하기`를 누르면 안내 문장이 나오고 아무것도 깨지지 않는다.
4. 코드 확인: `node tests/core.test.js` → `21개 모두 통과`.

## AI와 나의 판단

① **AI에게 맡긴 일** — 신호 감지 정규식과 논문 수치를 코드로 옮기는 일, 화면과 서버리스 프록시 코드, 테스트 21개, README 작성, 브라우저에서의 동작 점검.

② **내가 직접 판단한 일** — 논문의 어느 결과를 앱으로 만들지(네 가지 실험을 하나로 섞기로 결정), 대상 사용자, 3번 기능에 LLM을 넣을지와 어느 서비스(Gemini 무료 티어)를 쓸지, Vercel 가입과 GitHub 저장소 `T13` 생성, API 키를 Vercel 환경변수에 직접 입력, 공개 범위와 12번 사이트 연결 방식.

③ **AI 제안을 따르지 않은 일** — AI는 "핵심 기능은 키 없이 두고 LLM은 방문자가 자기 키를 넣을 때만 쓰는 선택 기능"으로 줄이자고 제안했는데, 나는 서버리스 프록시로 LLM을 앱에 직접 붙이는 쪽을 택했다. 그래서 키는 Vercel 환경변수에만 두고 남용 방지 제한(출처 검사, 분당 5회, 길이 제한)을 따로 넣었다.
