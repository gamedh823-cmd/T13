# 3차(최종) 계획 — 논문이 못 본 곳에서 앱의 가설을 검증한다

작성: 2026-10-23 · 앱: https://gamedh823-cmd.github.io/T13/

## 1. 논문은 무엇을 했나

- 논문(HW10)은 프롬프트에 곁들인 신호(예시, 다수 의견, 전문가 역할, 토론)가 AI의 답을 바꾸는지 ChatGPT·Gemini·Claude에 같은 횟수로 물었다.
- 결과: 신호는 답의 **모양**(길이·형식·색 구성)을 분명히 바꿨지만, **정답과 입장**은 대체로 바꾸지 못했다. 전문가 한 줄과 토론은 정답률을 그대로 두었다.
- 한계: 정답이 하나인 **계산·세기 문제**였고, 대부분 만점이라 차이가 드러날 여지가 없었다(천장 효과).

## 2. 앱은 무엇을 반증하려 하나

> 논문에서는 "곁들인 말은 정답을 못 바꾼다"고 했지만, **정답이 정해져 있지 않은 질문**(추천, 기획, 글쓰기, 조언 등)은 사정이 다를 수 있다. 이런 질문은 누가·언제·어디서·무엇을·왜·어떻게(육하원칙) 같은 정보가 없으면 AI가 평균적인 답을 내놓는다. 그 정보를 채워 주면 사용자가 **원하는 답**을 더 얻을 수 있지 않을까.

- **앱의 가설(H-앱)**: 답이 열린 질문에서, 육하원칙 정보를 채워 구체화한 프롬프트는 원문보다 **사용자가 원하는 답에 더 가까운 답**을 낸다.
- **반증 조건**: 평가에서 개선본이 원문보다 나아지지 않으면(차이가 없거나 원문이 더 낫다) 가설은 기각된다.
- 논문이 보지 못한 영역을 앱이 직접 확인하는 것이므로, 논문의 결과를 뒤집는 게 아니라 **적용 범위를 넓혀 시험**하는 일이다.

## 3. 실험 설계

| 항목 | 내용 |
|---|---|
| 질문 | 답이 열린 질문 24개: 추천(메뉴·장소·선물), 기획(행사·일정), 글쓰기(문구·소개), 조언(공부·진로) 각 6개. 개인정보 없이 직접 만든다 |
| 의도 기록 | 질문마다 사용자의 실제 의도(상황·조건·원하는 형식)를 한 줄로 적고, **의도 체크리스트 3~5개**를 답을 보기 전에 정한다 |
| 조건 A | 원문 그대로(예: "저녁 메뉴 추천해줘") |
| 조건 B | 앱이 만든 개선본(육하원칙 정보를 채운 프롬프트). 앱이 지어낸 정보가 없도록 정보는 의도 기록에서만 가져온다 |
| 모델 | 같은 AI(Gemini), 새 대화, 질문×조건당 3회, 순서 무작위 |
| 평가 | 블라인드(어느 쪽이 A·B인지 가림): ① 의도 체크리스트 충족 개수 ② 평가자 2~3명의 "원하는 답에 가까운 정도" 1~5점과 둘 중 고르기 |
| 수치 | 체크리스트 충족률 평균(A vs B), B 선택 비율, 평균 점수 차와 신뢰구간(부트스트랩), 부호검정 |
| 부가 지표 | 답 길이·항목 수(논문이 본 "모양"의 변화도 함께 보고) |

## 4. 결과 해석표 (결과가 어떻게 나와도 공개한다)

| 결과 | 해석 |
|---|---|
| B가 더 낫다(충족률·선택 모두) | 가설 지지. 표본 크기와 함께 "열린 질문에서는 구체화가 도움이 된다"로 보고 |
| 차이가 없다 | 논문처럼 "모양만 바뀌고 만족도는 비슷"으로 보고. 앱의 가치는 "길이·모양 조절"로 정리 |
| A가 더 낫다 | 개선 방식의 문제를 분석해 고치고 그대로 보고 |

## 5. 앱 개선 (피드백 반영)

| 개선 | 근거 |
|---|---|
| 첫 화면에서 스크롤 없이 입력·점검 | 동료 A의 반응 |
| AI 제안이 원문에 없는 설정("수제 디저트", "20~30대")을 지어내지 않고 빈칸으로 두기 | 직접 사용 |
| "원문 vs 개선본 답 비교" 기능(원문과 개선본의 답을 나란히 표시) | 가설 검증을 앱 안에서 보여 주기 위해 |
| "만든 이유" 문구 정정: "더 좋은 정보"를 목표가 아니라 검증할 가설로 | 논문 결과와의 정합성 |
| 라벨 116개 직접 검토, 알려진 약점 보강, 보류용 20개 최종 평가 | 2차 "다음에 할 일" |

## 6. 일정과 역할

1. 질문 24개와 의도 체크리스트 작성(나)
2. 실험 스크립트: A/B 프롬프트로 Gemini 호출·저장(AI), 분당 5회 제한을 지켜 천천히 실행
3. 블라인드 평가 시트(AI가 만들고) 평가자 2~3명이 채점(동료)
4. 집계·수치화 스크립트와 결과 보고 절 추가(AI)
5. 앱 개선과 제출문(나·AI)

## 7. 한계 (미리 적어 둔다)

- 질문 24개와 평가자 2~3명이라 결론은 "경향"이다. 표본 크기를 항상 같이 적는다.
- 사용자의 의도를 내가 직접 정하므로, 실제 사용자 의도와 다를 수 있다.
- 한 AI(Gemini)만 쓰므로 다른 AI로 일반화할 수 없다.
- 답이 열린 질문의 "원하는 답" 평가는 주관이 들어간다. 그래서 체크리스트(사전 기준)와 블라인드 평가를 함께 쓴다.
