# 최종 제출문 — 프롬프트 신호 점검기

앱: https://gamedh823-cmd.github.io/T13/ · 소스: https://github.com/gamedh823-cmd/T13 · 실험 보고서: `docs/실험결과.md`

## 이번에 만든 것

열린 질문 24개를 A 원문 / B 원문+육하원칙 / C 원문+신호만으로 Gemini에 물어 144개 답을 블라인드 채점했다. 의도 충족률은 A 22%, B 98%, C 26%(C−A는 차이 없음, 신호를 붙인 답은 94% 길어짐). 결과를 앱 맨 아래에 공개했고, 입력·결과를 나란히 보는 화면으로 바꾸고, 판정 신고를 Vercel 함수로 디스코드 웹훅에 자동 전송하게 했다. 테스트 64개 통과.

## 확인하는 방법 (3단계 이내)

1) 앱 맨 아래 "가설 검증 실험"을 펼쳐 A 22%·B 98%·C 26% 표와 신뢰구간을 본다. 2) 입력창에 "동네 카페 오픈 홍보 문구 써줘"를 넣고 점검한 뒤 AI 제안을 누르면 지어낸 설정 없이 [빈칸]이 나오는지, 점검 결과가 입력창 옆 오른쪽 창에 나오는지 확인한다. 3) 저장소에서 docs/실험결과.md를 읽고 node tests/exp.test.js 등 테스트 6개 파일이 통과하는지, node exp/analyze.js로 표를 다시 만들어 같은지 확인한다.

## 바뀐 점과 그 이유

앱의 "더 좋은 정보를 얻게 한다"를 주장이 아니라 검증 대상으로 바꿨다. 논문은 정답이 하나인 계산 문제에서 신호가 정답을 못 바꾼다고 했는데 그 실험은 천장 효과가 있었고, 열린 질문은 보지 못했다. A·B만 비교하면 B가 이기는 게 당연해서 신호만 붙인 통제 조건 C를 넣었다. 무료 한도로 gemini-3.5-flash가 중단돼 lite 모델로 처음부터 다시 돌렸다. 동료 반응(입력과 결과를 나란히 보고 싶다)과 사용 중 발견(AI 제안이 설정을 지어냄)도 고쳤고, 판정 신고는 복사 대신 Vercel 함수→디스코드 웹훅으로 자동 전송하게 했다.

## AI에게 맡긴 일과 내가 직접 판단한 일

AI: 질문 24개와 체크리스트 초안, 실험·채점·집계 코드, 통계, 앱 개선, 보고서. 나: 논문이 못 본 열린 질문에서 육하원칙의 효과를 수치로 검증하겠다는 방향과 "모양만 바뀌면 앱의 이유가 뭐냐"는 문제 제기, 속도 우선 결정, API 키 직접 설정, 결과 해석 확인. AI 제안을 따르지 않은 일: 이번 구간에는 없었다(실험 설계와 조건 C 추가를 AI가 제안했고 그대로 따랐다). 내가 시켰지만 AI가 하지 않은 일: 비밀값인 API 키를 AI가 찾아 넣는 것(내가 직접 넣음).

## 다음에 할 일

동료 2~3명의 블라인드 평가로 채점 모델과 사람 판단의 일치를 확인하고, 사용자가 앱 안내를 보고 실제로 정보를 채우는지 사용자 실험으로 재고, 육하원칙 6칸 중 어떤 칸이 가장 중요한지(칸을 빼며 비교), 다른 AI 모델로 반복하며, AI 초안인 라벨 116개를 직접 검토한다.

## 한계 (보고서에 자세히)

체크리스트가 의도 정보에서 나와 B에 유리한 구조라서 98%는 "AI가 받은 정보를 쓴다"는 기대된 결과에 가깝고, 의미 있는 건 C와의 차이와 효과의 크기다. 앱 자체의 효과(사용자가 정보를 채우는지)는 재지 않았다. 의도는 가상 상황, 채점은 Gemini, 질문 24개, 한 AI 계열이다.
