# 발표 대본 — 프롬프트 신호 점검기 (약 5분)

슬라이드 6장 기준. 괄호는 화면에 띄울 것.

## 1. 문제 (30초) — 슬라이드 1
(제목: 프롬프트에 곁들인 말은 AI의 답을 바꾸는가?)

"AI에게 물을 때 '전문가처럼 답해 줘', '단계별로 생각해 줘' 같은 말을 붙이면 더 좋은 답이 나온다고들 합니다. 저는 이전 과제(HW10)에서 이게 정말인지 논문 형태로 실험했습니다."

## 2. 논문의 결과 (40초) — 슬라이드 2
"정답이 하나인 계산 문제에서는 이런 말이 정답을 거의 못 바꿨습니다. 바꾼 건 답의 모양, 예를 들어 길이였습니다. 다만 그 실험은 정답이 하나인 문제였고, 천장 효과도 있었습니다."

## 3. 앱 (60초) — 슬라이드 3
(앱 화면: https://gamedh823-cmd.github.io/T13/ 실시간 시연)
"이 결과로 앱을 만들었습니다. 문장을 넣으면 논문에서 다룬 신호가 들어 있는지 점검하고, 빠진 정보를 짚어 AI 제안으로 고쳐 줍니다. 신호 판정은 직접 모은 문장 2000개로 학습한 분류기와 규칙을 함께 씁니다. 예를 들어 '동네 카페 오픈 홍보 문구 써줘'를 넣으면 지어낸 설정 없이 [빈칸]으로 남겨 둡니다."

## 4. 가설과 실험 (70초) — 슬라이드 4
"그런데 논문은 열린 질문을 보지 못했습니다. 그래서 앱의 가설을 따로 세웠습니다. '답이 정해지지 않은 질문에서는 육하원칙 정보를 넣으면 원하는 답을 더 얻는다.'

추천·기획·글쓰기·조언 질문 24개를 세 조건으로 물었습니다. A는 원문, B는 원문에 육하원칙 정보를 더한 것, C는 원문에 논문의 신호만 붙인 것입니다. C는 정보 없이 말만 붙인 대조군입니다. 답 144개를, 조건을 가린 다른 AI가 미리 정해 둔 체크리스트로 채점했습니다."

## 5. 결과 (80초) — 슬라이드 5
(표: A 22% / B 98% / C 26%)
"의도를 충족한 비율은 A 22%, B 98%, C 26%였습니다. B가 A보다 평균 76.7%p 높았고, 24개 질문 모두에서 같은 방향이었습니다. C는 A와 차이가 없었고, 답만 94% 길어졌습니다.

정리하면, 논문의 가설인 '곁들인 신호가 답을 바꾼다'는 모양에서만 맞았고, 앱의 가설인 '구체적인 정보가 원하는 답을 만든다'는 이 실험에서 지지됐습니다. 두 가설은 서로 다른 주장입니다."

## 6. 한계와 다음 (40초) — 슬라이드 6
"한계도 분명합니다. 체크리스트가 사용자 정보에서 나와서 B에 유리한 구조입니다. 그래서 98% 자체보다 신호만 붙인 C와의 차이가 의미 있습니다. 채점은 사람이 아니라 Gemini이고, 질문은 24개, 모델은 한 계열입니다. 실제 사용자가 앱 안내를 보고 정보를 채우는지는 재지 않았습니다.

다음에는 동료의 블라인드 평가로 채점 모델을 검증하고, 육하원칙 6칸 중 어떤 칸이 가장 중요한지 보겠습니다."

## AI와 나의 판단 (제출 양식과 같은 내용, 질문 대비)
- AI: 질문 24개와 체크리스트 초안, 실험·집계 코드, 통계, 앱 개선, 보고서.
- 나: 논문이 못 본 열린 질문에서 육하원칙 효과를 수치로 검증하겠다는 방향, "모양만 바뀌면 앱의 이유가 뭐냐"는 문제 제기, 속도 우선 결정, API 키 직접 설정, 결과 해석 확인.

## 예상 질문
- **B가 이기는 게 당연하지 않나?** 맞다. 그래서 대조군 C를 넣었다. 정보 없이 같은 길이의 말만 붙이면 26%였다. 의미는 C와의 차이와 효과의 크기에 있다.
- **채점을 믿을 수 있나?** 글자로 확인 가능한 항목 24개 중 23개가 일치했고 답 길이와 충족률 상관은 −0.02였다. 사람 평가와의 일치는 아직 확인하지 못했다.
- **논문 결론이 틀렸다는 건가?** 아니다. 열린 질문에서도 신호는 모양만 바꿨다. 논문의 결론은 유지된다.
- **앱의 효과를 증명했나?** 아니다. 정보를 채울 때 얻는 이득의 크기를 재었고, 사용자가 실제로 채우는지는 다음 과제다.
