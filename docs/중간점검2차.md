# 중간 점검 2차 제출 — 신호 감지 정확도 개선

제출일: 2026-10-20 · 앱: https://gamedh823-cmd.github.io/T13/ · 소스: https://github.com/gamedh823-cmd/T13

## 이번에 만든 것 (1차 이후)

1차에서 정규식을 학습한 분류기로 바꿨다(개발용 96개에서 F1 0.82 → 0.94). 그런데 앱을 직접 써 보니 신호 체크가 충분히 믿음직하지 않다는 느낌이 있었다. 모델이 확신이 없는 문장도 "있다/없다"로만 잘라 보여 주고, 틀려도 알릴 길이 없었다. 그래서 이번에는 **판정을 믿을 수 있게 보여 주는 것**과 **실제로 틀린 문장을 모으는 통로**를 만들었다.

1. **확신도와 약한 신호 표시**: 확정한 신호 카드에 "확신도 97%"를 붙였다. 확정 기준(0.4)에는 못 미치지만 0.2 이상인 신호는 버리지 않고 체크리스트에 `△`(약한 신호)로 따로 보여 준다. 예를 들어 "이거 어떻게 하면 좋을까?"는 열린 추천으로 확정하지 않고 약한 신호 36%로만 표시한다.
2. **"판정이 틀렸나요?" 신고 패널**: 맞는 신호에 체크하고 누르면 문장(앞 300자)과 체크한 신호, 앱이 낸 판정이 JSON 한 줄로 복사된다. 서버로 보내지 않고 개인정보를 지우라고 안내한다. 이 문장들을 라벨과 학습 데이터로 쓴다.
3. **실제 사용 문장 평가 세트** (`eval/real_use.json`): 내가 앱에 직접 넣어 본 문장 4개를 따로 모았다. `node eval/score.js --set real --engine <엔진>`으로 잰다. 기존 규칙은 3개 중 2개, 학습 모델은 3개 중 3개의 신호를 잡았다(정답 신호가 있는 문장 3개, 없는 문장 1개). 4문장뿐이라 의미 있는 수치는 아니고, 이 세트를 계속 늘리기 위한 통로다.
4. 테스트 47개(core 31, eval 6, ml 10)가 모두 통과한다. 새로 넣은 것: 약한 신호는 확정 신호에 섞이지 않는지, 확정 신호에 확신도가 붙는지, 실제 사용 세트가 형식에 맞고 개발·보류용 문장과 겹치지 않는지.

## 확인하는 방법 (3단계 이내)

1. https://gamedh823-cmd.github.io/T13/ 에서 `이거 어떻게 하면 좋을까?`를 넣고 `점검하기`를 누른다. "열린 추천 요청"이 확정(✔)되지 않고 `△`로 표시되고 "약한 신호 1가지"와 퍼센트가 보이면 통과.
2. `고양이 이름 후보 좀 지어 줘`를 점검한다. 열린 추천 ✔와 카드의 "확신도 N%"가 보이는지 본다. 맨 아래 "판정이 틀렸나요?"에서 체크를 바꾸고 복사 버튼을 누르면 `{"text":...,"signals":[...],"앱판정":[...]}` 한 줄이 복사되면 통과.
3. 저장소에서 `node tests/core.test.js && node tests/eval.test.js && node tests/ml.test.js`가 31·6·10개 모두 통과하는지 보고, `node eval/score.js --set real --engine model --thr 0.4`와 `--engine rules`로 실제 사용 문장 점수를 비교한다.

## 바뀐 점과 그 이유

- **버리던 애매한 판정을 "약한 신호"로 보여 주게 바꿨다.** 앱을 써 보고 "신호 체크가 빡빡하지 않다"고 느꼈는데, 모델이 0.3~0.4쯤으로 망설인 신호는 지금까지 그냥 없는 것으로 처리됐기 때문이다. 확정과 무시로 자르지 않고 확률을 보여 주면 사용자가 판단할 수 있다. 약한 신호는 확정에 넣지 않아서 1차의 점수(개발용 F1 0.94)는 그대로다.
- **틀린 판정을 받는 통로를 만들었다.** 라벨은 AI 초안이고 학습 문장은 대부분 합성이라, 점수가 좋아도 실제 문장에서 틀릴 수 있다는 것을 열린 추천 오탐으로 확인했다. 실제로 틀린 문장이 가장 가치 있는 데이터라서, 사용자가 쉽게 알릴 수 있게 했다.
- **정밀 감지(AI 판별) 모드는 이번에도 넣지 않았다.** 학습 모델만으로 앱이 서버 없이 빨리 동작하고, AI 호출의 비용·한도를 지고 갈 만큼 개선된다는 근거가 아직 없다. 최종 제출 전에 다시 판단한다.
- 계획서 2차 항목 중 "라벨 검토 반영"과 "남은 약점 보강"은 아직 못 했다(아래 다음에 할 일).

## AI에게 맡긴 일과 내가 직접 판단한 일

**AI(Claude)에게 맡긴 일**: 확신도·약한 신호 표시 코드, 판정 신고 패널, 실제 사용 평가 세트와 채점 옵션, 테스트, 문서.

**내가 직접 판단한 일**: 앱을 써 보고 "신호 체크가 빡빡하지 않다"는 불만을 짚은 것, 1차 제출 직후 2차로 넘어가기로 한 것. (라벨 기준 검토는 아직 하지 못했다.)

**AI 제안을 따르지 않은 일**: (AI 제안과 내 판단이 갈린 새 사례가 이번 구간에는 없었다. 1차 제출문에 적은 사례가 마지막이다. 이번 구간에서 AI가 정한 약한 신호 기준(0.2)과 신고 패널의 수집 방식은 내가 아직 확인하지 않았다.)
