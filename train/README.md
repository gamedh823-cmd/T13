# train — 신호 감지 학습

규칙(정규식) 대신 학습한 분류기로 프롬프트의 신호를 잡습니다. 앱(`index.html`)은 이 모델을 불러서 쓰고, 불러오지 못하면 규칙으로 돌아갑니다.

## 데이터: 정확히 2000개

| 파일 | 개수 | 설명 |
|---|---|---|
| `data/train.jsonl` | 1432 | `gen.py`가 내가 쓴 표현 사전(신호 문구·질문 본문·주제)을 조합해 만든 합성 문장. 이 중 253개는 학습에 쓰지 않은 "처음 보는 표현" 검증용 |
| `data/extra_handwritten.jsonl` | 291 | 한 문장씩 직접 쓴 문장(반말·존댓말·메신저체·영어·긴 문장). 58개는 새 말투 검증용 |
| `data/extra_hard.jsonl` | 277 | 열린 추천과 헷갈리는 문장 보강(방법을 묻는 "없을까", 조언 질문, 단어만 언급, 후보를 구하는 요청). 55개는 검증용 |
| **합계** | **2000** | 학습 1634 + 검증 366 |

`python train/extra2_gen.py`가 합계가 2000이 아니면 멈춥니다. 개인정보는 없습니다. 평가용 라벨(`eval/labels.json`)의 문장은 자동으로 뺐습니다.

## 파일

| 파일 | 설명 |
|---|---|
| `gen.py`, `extra_gen.py`, `extra2_gen.py` | 위 데이터를 만드는 스크립트(seed 고정, 같은 결과) |
| `train.py` | 글자 n-gram TF-IDF + 신호별 로지스틱 회귀 학습, 평가 출력, `model.json`·`model.js` 저장 |
| `model.json` / `model.js` | 학습한 가중치(어휘 6000개, 약 0.5MB). `model.js`는 같은 내용을 JS로 감싼 것이라 `index.html`을 더블클릭해서 열어도 읽힌다 |

```bash
python train/gen.py && python train/extra_gen.py && python train/extra2_gen.py   # 데이터 다시 생성
python train/train.py --thr 0.4 --errors                                         # 학습과 평가 (scikit-learn 필요)
node eval/score.js dev --engine model --thr 0.4                                  # 같은 라벨로 엔진 비교
```

## 결과

### 열린 추천 문제 (사용자가 앱에서 직접 본 오탐)

기존 규칙은 `없을까`, `새로운 방법`, `추천` 같은 단어만 봐서 "엑셀에서 합계 구하는 방법이 없을까?", "추천 알고리즘이 뭐야"를 열린 추천으로 잡았습니다. 이런 문장 20개(`kind: hard`)를 평가용 라벨에 더해 같은 세트로 다시 쟀습니다(개발용 96개).

| 엔진 | 열린 추천 오탐(정답 14개 중) | 어려운 문장 정확 일치 | 전체 F1 |
|---|---|---|---|
| 기존 규칙(기준선, 정밀도 0.63) | 6개 | 7/16 (44%) | 0.82 |
| 학습 모델, 임계값 0.3 (정밀도 0.92) | 1개 | 15/16 (94%) | 0.95 |
| 학습 모델, 임계값 0.4 (앱에 적용, 정밀도 1.00) | 0개 | 15/16 (94%) | 0.94 |

앱은 오탐(엉뚱한 신호)을 줄이는 쪽이 낫다고 보고 임계값 0.4를 씁니다(전체 정밀도 0.97, 재현율 0.92).

**정밀도 1.00을 믿으면 안 되는 이유**: 열린 추천 정답이 14개뿐이라 오탐 0개가 곧 1.00이 됩니다(임계값 0.3에서는 오탐 1개로 0.92). 또 평가용 어려운 문장과 학습용 어려운 문장을 같은 사람이 비슷한 방식으로 썼기 때문에 점수가 실제보다 높을 수 있습니다. 재현율은 0.79(정답 14개 중 11개)라서 열린 추천을 놓치는 경우도 있습니다.

### 학습에 쓰지 않은 검증 세트

| 검증 세트 | 개수 | F1 (임계값 0.3) |
|---|---|---|
| 처음 보는 표현(합성) | 253 | 0.93 |
| 직접 쓴 새 말투 | 113 | 0.85 |
| 평가용 라벨 dev | 96 | 0.95 |

직접 쓴 문장을 더하기 전(1179개 학습)에는 같은 세트들에서 0.87 / 0.74 / 0.94(dev 80개 기준)였습니다.

## 한계

- 학습 문장 대부분이 조합으로 만든 합성 문장이고 말투가 실제 사용자와 다릅니다. 직접 쓴 문장도 한 사람(과 AI)이 쓴 말투입니다.
- 검증 세트가 작아서(113개, 96개) 한 문장이 점수를 크게 흔듭니다.
- 임계값은 개발용 라벨을 보고 고른 값이라 낙관적입니다. 보류용(holdout) 20개는 아직 재지 않았습니다.
- 평가용 라벨은 AI가 초안을 쓰고 사용자가 검토하는 중입니다. "열린 추천" 정의(후보·아이디어를 구하는 요청이고 방법·조언을 묻는 건 아님)도 이 기준으로 붙였습니다.
- 모델이 잘 틀리는 곳: 영어 문장의 다수 의견 오탐, "브레인스토밍이 뭐야" 같은 단어 설명 요청.
