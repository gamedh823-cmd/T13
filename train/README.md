# train — 신호 감지 학습

규칙(정규식) 대신 학습한 분류기로 신호를 잡아 보는 실험입니다. 아직 앱(`core.js`)에는 연결하지 않았습니다.

| 파일 | 설명 |
|---|---|
| `gen.py` | 학습용 문장 생성. 내가 쓴 표현 사전(신호 문구·질문 본문·주제)을 조합해 만든 합성 데이터 약 1400개, 개인정보 없음. 평가용 라벨(`eval/labels.json`) 문장은 자동으로 제외 |
| `data/train.jsonl` | 생성된 학습 데이터(`train` 1179, 학습에서 못 본 표현으로 만든 `val_unseen` 253) |
| `train.py` | 글자 n-gram TF-IDF + 신호별 로지스틱 회귀 학습, 평가 출력, `model.json` 저장 |
| `model.json` | 브라우저에서 쓸 가중치(어휘 6000개, 약 0.5MB) |

```bash
python train/gen.py              # 데이터 다시 생성 (seed 고정, 같은 결과)
python train/train.py --errors   # 학습하고 평가, 틀린 사례 출력 (scikit-learn 필요)
```

## 지금까지 결과 (개발용 dev, 사람이 검토하는 라벨 80개)

| 방식 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| 기존 규칙(기준선) | 0.92 | 0.83 | 0.87 |
| 학습 모델, 임계값 0.5 | 1.00 | 0.80 | 0.89 |
| 학습 모델, 임계값 0.3 | 0.98 | 0.89 | 0.94 |

- 임계값 0.3은 dev 점수를 보고 고른 값입니다. dev에 맞춘 값이라 낙관적이고, 보류용(holdout) 16개는 아직 재지 않았습니다.
- 학습에서 못 본 표현(`val_unseen`)에서는 임계값 0.3일 때 F1 0.87, 0.5일 때 0.77로 내려갑니다. 처음 보는 표현을 잡는 힘은 아직 약합니다.

## 엔진 비교 (개발용 dev 80개, 같은 라벨·같은 채점)

브라우저/Node용 추론은 `ml.js`(파이썬과 확률 차이 최대 0.00003). 채점은 `node eval/score.js dev --engine <엔진>`.

| 엔진 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| rules (기준선, 정규식) | 0.92 | 0.83 | 0.87 |
| model, thr 0.3 | 0.98 | 0.89 | 0.94 |
| union(규칙+모델), thr 0.3 | 0.91 | 0.97 | 0.94 |
| union, thr 0.4 | 0.93 | 0.95 | 0.94 |
| vote(모델 + 모델이 확인한 규칙), thr 0.4, low 0.05 | 0.93 | 0.95 | 0.94 |

세 방식이 비슷해서(0.93~0.94) 80개로는 우열을 가리기 어렵습니다. 합친 방식은 재현율이 높고 모델 단독은 정밀도가 높은 경향이 있습니다. 어느 쪽을 쓸지는 데이터를 늘린 뒤 다시 재서 정합니다. 임계값은 dev를 보고 고른 값이라 낙관적입니다.
