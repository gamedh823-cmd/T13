# exp — 가설 검증 실험

**질문**: 답이 정해져 있지 않은 질문(추천·기획·글쓰기·조언)에서, 육하원칙(누가·언제·어디서·무엇을·왜·어떻게) 정보를 채우면 사용자가 원하는 답에 더 가까워지는가?

논문(HW10)은 곁들인 말(전문가 역할·토론 등)이 답의 모양은 바꾸지만 정답은 못 바꾼다고 했는데, 그 실험은 정답이 하나인 계산 문제였다. 이 실험은 논문이 보지 못한 열린 질문에서 같은 질문을 던진다. 결과가 어떻게 나와도 `results/summary.md`에 그대로 공개한다.

## 설계

| 항목 | 내용 |
|---|---|
| 질문 | 24개(추천·기획·글쓰기·조언 각 6개). `build_questions.py`가 `questions.json`을 만든다. 개인정보 없음 |
| 사용자 의도 | 질문마다 육하원칙 6칸(facts)과, **답을 보기 전에** 정한 체크리스트 5개(check) |
| 조건 A | 원문 그대로 |
| 조건 B | 원문 + 육하원칙 정보 6줄 |
| 조건 C | 원문 + 논문이 실험한 신호(전문가 역할·토론·단계별·다수 의견)만, 새 정보 없음 |
| 답변 모델 | `gemini-3.5-flash-lite`, 질문×조건당 2회, 새 요청마다 대화 없음 |
| 채점 모델 | `gemini-3.1-flash-lite`(답변 모델과 다른 모델), 조건을 알려 주지 않는 블라인드, 체크리스트 5개 true/false와 의도 근접 점수 1~5 |
| 집계 | 질문별로 회차 평균 → 조건 비교(평균 차이, 부트스트랩 95% 신뢰구간 10000회, 부호검정) |
| 사람 평가 | `sheet.js`가 블라인드 시트를 만들고 `human.js`가 집계(채점 모델과 사람의 일치 확인용) |

**왜 조건 C가 있나**: 체크리스트가 사용자 의도 정보에서 나오므로 A와 B만 비교하면 B가 이기는 게 당연하다. 정보 없이 신호만 붙인 C와 비교해서, 같은 길이의 말이라도 정보가 있어야 의도에 맞는지를 본다.

## 실행 (Node 18+, 설치할 것 없음)

```bash
node exp/run.js dry                         # 프롬프트와 호출 횟수만 확인(API 안 씀)
node exp/run.js answers --runs 2            # 답변 받기 -> results/answers.jsonl
node exp/run.js judge                       # 채점 -> results/judgements.jsonl
node exp/analyze.js                         # 집계 -> results/summary.md, summary.json, summary_data.js
node exp/sheet.js                           # 사람 블라인드 평가 시트 -> sheet/
```

- 키: 환경변수 `GEMINI_API_KEY` 또는 `exp/.env` 파일의 `GEMINI_API_KEY=...`(이 파일은 git에 올리지 않는다).
- 여러 창에서 나눠 돌리려면 `--shard 1/3`, `2/3`, `3/3`. 멈춰도 다시 실행하면 이어서 한다.
- 답이 잘리면(`finish`가 STOP이 아님) `answers.jsonl`에 기록되고 집계에서 센다.

## 한계 (미리 적어 둔다)

- 질문 24개이고 한 AI 계열(Gemini lite)이라 다른 AI로 일반화할 수 없다.
- 사용자 의도는 내가 만든 **가상 상황**이다. 실제 사용자의 의도와 다를 수 있다.
- 채점은 사람이 아니라 Gemini가 했다. 조건은 가렸지만 채점 모델의 편향이 있을 수 있어, 사람 평가와의 일치를 따로 본다.
- 무료 한도 때문에 `gemini-3.5-flash`(비-lite)는 쓰지 못했다. 처음 시도에서 한도 초과로 중단해 그 결과는 버리고 lite 모델로 처음부터 다시 돌렸다.
