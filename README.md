# 프롬프트 신호 점검기

AI에게 질문을 쓰는 사람이 프롬프트를 붙여 넣으면, 그 안의 **신호 8가지**(논문이 직접 실험한 토론 지시·전문가 역할·다수 의견·이미지 구체성 4가지, 선행 연구 기반 풀이 과정·예시·내 의견·열린 추천 4가지)가 답에 주는 영향을 논문 결과로 짚어 주고, 빠진 정보는 채워 주고 불필요한 정보는 제외시켜 **더 구체적인 질문**으로 고치도록 방향을 잡아 주는 앱입니다.

근거 논문: 「프롬프트에 곁들인 신호는 AI의 답을 바꾸는가? — ChatGPT·Gemini·Claude 세 AI에 대한 반복 실험」 (유지원, 2026) — https://gamedh823-cmd.github.io/T10/paper.pdf

## 만든 이유

논문(HW10)은 프롬프트에 곁들인 말(전문가 역할, 토론, 예시 등)이 AI 답의 **길이와 모양**은 분명히 바꾸지만 **정답**은 거의 바꾸지 못했다고 보고했습니다. 다만 그 실험은 정답이 하나인 계산·세기 문제였고 대부분 만점이라 차이가 드러날 여지가 없었습니다.

이 앱은 **답이 정해져 있지 않은 질문**(추천·기획·글쓰기·조언)에서는 다를 수 있다는 가설을 검증하려고 만들었습니다. 이런 질문은 누가·언제·어디서·무엇을·왜·어떻게(육하원칙) 정보가 없으면 AI가 평균적인 답을 내놓습니다. 그 정보를 채워 주면 사용자가 **원하는 답**에 더 가까워지는지를 `exp/`의 실험(원문 A / 육하원칙 정보 B / 논문의 신호만 C)으로 재고, 결과는 `exp/results/summary.md`에 어떻게 나와도 공개합니다. 실험 결과가 나오기 전에는 "질문을 고치면 더 좋은 답이 나온다"고 주장하지 않습니다.

### 화면 배치 (넓은 화면은 가로로)

화면 폭이 1000px 이상이면 위에서 아래로 길게 스크롤하지 않도록 두 칸으로 나눕니다.

- **왼쪽:** 1 입력 → 2 "더 나은 프롬프트 제안 받기" → "틀린 판정 신고하기" 버튼
- **오른쪽 창:** 점검 결과(신호 8가지, 신호별 논문 결과, 답 길이 변화)가 나오고, "AI에게 고친 프롬프트 받기"를 누르면 **고친 프롬프트**로, "틀린 판정 신고하기"를 누르면 신고 **체크 목록**으로 바뀝니다. 각 창 맨 위의 "← 점검 결과 보기"로 돌아옵니다. 한 번에 창 하나만 보입니다.
- **좁은 화면(폰):** 창 전환 없이 한 줄로 쌓이고, 순서는 입력 → 점검 결과 → 제안 → 고친 프롬프트 → 신고입니다.
- 제목 영역(큰 제목·근거 논문 카드·3단계 안내)은 처음 모양을 그대로 둡니다. 신호·확신도 설명 같은 결과 카드의 글씨는 16px로 키우고 줄 간격을 넓혔습니다.

## 내 컴퓨터에서 실행 (3단계, 설치 없음)

1. ZIP을 풀거나 이 저장소를 내려받아 폴더를 엽니다.
2. `index.html`을 더블클릭합니다. (브라우저에서 열림)
3. 화면의 예시 버튼 하나를 눌러 점검 결과가 나오면 성공입니다.

> 파일로 직접 열면 3번 "AI에게 고친 프롬프트 받기" 버튼은 서버가 허용한 주소가 아니라서 동작하지 않고, 대신 규칙 제안이 보입니다. 1·2번 기능은 인터넷 없이 모두 동작합니다.

## 테스트

```bash
node tests/core.test.js && node tests/eval.test.js && node tests/ml.test.js && node tests/report.test.js && node tests/exp.test.js
```

Node 18 이상만 있으면 됩니다. 여섯 파일이 각각 `31개`, `6개`, `10개`, `4개`, `8개`, `5개 모두 통과`를 내면 통과입니다(합계 64개).

## 환경 변수 (3번 기능과 판정 신고를 직접 배포할 때만)

소스와 화면에는 키가 없습니다. Vercel 프로젝트의 Environment Variables에 이름만 맞춰 넣습니다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | 예 | Google AI Studio에서 발급한 Gemini API 키 |
| `GEMINI_MODEL` | 아니오 | 기본값 `gemini-2.5-flash` |
| `DISCORD_WEBHOOK_URL` | 판정 신고를 쓸 때 | 신고를 받을 디스코드 채널의 웹훅 주소 (Production에만 등록) |

키가 없거나 서버가 실패해도 앱은 멈추지 않고 규칙 기반 제안만 보여 줍니다. 프록시는 허용 출처 검사, 분당 5회(IP당) 제한, 입력 4000자 제한(화면 점검 한도와 같음), 출력 500토큰 제한을 둡니다.

## 판정 신고 → 디스코드 (Vercel 함수 + 웹훅)

신호 판정이 틀렸을 때 사용자가 오른쪽 창의 "판정 신고"에서 체크하고 **전송하기**를 누르면, 신고가 개발자 디스코드 채널로 자동으로 갑니다.

```
브라우저(전송하기) → Vercel 함수 /api/feedback → 디스코드 웹훅 → #프롬프트-신호-점검기 채널
```

- 웹훅 주소는 소스·화면에 없고 Vercel 환경변수 `DISCORD_WEBHOOK_URL`에만 있습니다. 주소를 화면에 두면 누구나 채널에 글을 보낼 수 있어서 서버 함수를 거칩니다.
- 함수는 허용 출처만 받고, IP당 분당 3회로 제한하고, 문장은 3000자까지만 받고, `@everyone` 같은 멘션이 알림을 울리지 않게 막습니다.
- 디스코드 카드에는 입력한 문장 전체, 앱이 잡은 신호, 사용자가 체크한 신호, 둘의 차이(앱만 잡음 / 사용자만 체크)가 나옵니다. 같으면 남보라, 다르면 주황 띠입니다.
- 누르기 전에는 아무것도 보내지 않고, 전송에 개인정보를 넣지 말라고 화면에 안내합니다.
- 환경변수가 없으면 "전송 기능이 아직 켜져 있지 않아요"가 뜨고 나머지 기능은 그대로 동작합니다. 형식 테스트는 `node tests/feedback.test.js`입니다.

### 신고로 모델을 고친 사례 (2026-10-28)

![디스코드로 온 판정 신고 두 건](docs/screens/06_%EB%94%94%EC%8A%A4%EC%BD%94%EB%93%9C_%ED%8C%90%EC%A0%95%EC%8B%A0%EA%B3%A0.png)

| 신고 | 앱 판정 | 사용자 체크 | 의미 |
|---|---|---|---|
| “당신은 이 분야에서 20년 경력을 가진 최고 수준의 전문가입니다. 9876 × 6789는 얼마인가요?” | 전문가 역할 | 전문가 역할 | 같음. 앱 판정이 맞다고 확인 |
| “떡볶이 대신 먹을 거 없나” | 없음 | 열린 추천 | **다름. 앱이 열린 추천을 놓침** |

두 번째 신고처럼 앱이 놓친 문장은 이렇게 고쳤습니다.

1. 신고된 문장 자체는 **학습에 넣지 않고** 평가용 실제 사용 문장(`eval/real_use.json`의 R006)으로만 추가했습니다. 같은 문장을 학습시키고 맞았다고 하면 점수가 부풀려지기 때문입니다.
2. 같은 형태("~ 대신 먹을 거 없나", "~ 말고 먹을 만한 거 없을까", "볼 만한 영화 없나" 등)의 문장 12개를 직접 써서 `train/extra2_gen.py`의 열린 추천 예시에 넣었습니다. 합성 문장 일부를 대신 빼서 전체는 2000개로 유지했습니다.
3. 다시 학습한 결과 신고된 문장의 열린 추천 확신도가 0%대에서 0.89로 올라 신호로 잡힙니다. 개발용 세트 점수는 거의 그대로입니다(정밀도 0.99, 재현율 0.94, F1 0.96). 처음 보는 표현 F1은 0.92에서 0.91로 약간 낮아졌습니다.
4. 방법을 묻는 “~하는 방법이 없을까?”는 여전히 신호 없음으로 남습니다.

즉 판정 신고는 "복사해서 보내는 것"이 아니라 **오판 문장이 디스코드로 오면 평가 세트에 추가하고 비슷한 문장으로 모델을 보강하는 순환**입니다. 다만 한 문장 신고로 모델이 일반적으로 좋아졌다고 말할 수는 없고, 보류용 20문장은 아직 재지 않았습니다.

앱에 들어간 데이터는 논문 본문에 공개된 집계 수치(표 9·12·14·15·18)와, 직접 쓰거나 조합해 만든 합성 학습 문장 2000개로 학습한 모델 가중치입니다. 개인정보가 없고, 입력한 프롬프트는 저장하지 않습니다.
